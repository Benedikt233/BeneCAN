# BeneCAN — ASC Graphic Viewer（V0.4）

> 仅供学习使用。

把上游工具导出的 `.asc` 日志变成类似 **Vector CANoe Graphic 窗口**的可视化与测量体验：
多行堆叠曲线、单坐标轴叠加、共享时间轴、单光标 / 双光标 ΔT 测量、Y 轴跟随缩放、值表、CSV/PNG 导出、图形布局保存，可选接入 DBC。

数据来源：`Vehicle_log_tool_AI` 的 zst2asc 转换产物（`logCAN{n}.asc`）。

> **关于名字**：V0.1 起本工具由 `SavvyCAN_AI` 更名为 **BeneCAN**。
> 开发初期借用了开源项目 [SavvyCAN](https://github.com/collin80/savvycan) 的降采样思路作为参考，
> 故当时以它命名；本项目与该项目**没有隶属或派生关系**，代码在评估后为自研实现。

## 一、快速开始

### 1. 源码运行（开发/自用）

```bash
pip install PySide6 pyqtgraph pyarrow numpy cantools
python main.py                      # 打开后手动选 ASC
python main.py "TestZone\logCAN8.asc"
python main.py "D:\日志解压目录"      # 目录也行：自动取里面最新的 .asc
```

### 2. 打包成单 exe（分发）

```bash
python -m PyInstaller benecan.spec --noconfirm
# 产物：dist\BeneCAN.exe（含示例 DBC，双击即用）
```

打包后的目录结构（用户侧）：

```
某个目录\
├─ BeneCAN.exe
├─ dbc\                     ← 把你自己的 DBC 放这里（例如 CH5.dbc）
│   ├─ example.dbc          ← 随包示例
│   └─ channel_map.json     ← 通道映射配置（程序自动生成/更新）
├─ logs\                    ← 运行日志（首次运行自动创建）
└─ 你的日志\
```

## 二、界面与操作

| 位置 | 功能 |
|---|---|
| 左侧树 | 通道 → 报文 ID → 信号；过滤框可按 ID/通道筛选；报文展开时**懒加载**信号 |
| 双击报文 | 自动挑选该报文最有信息量的前 6 个字段成行 |
| 展开报文 | 看逐字节画像（常量/枚举/模拟 + 取值数/范围）；有 DBC 时改为列 DBC 信号 |
| 图形区 | 滚轮缩放、拖动平移；任一行缩放其余行同步；右键可删行/上移/下移/置顶/清空 |
| 行内说明 | 每个坐标系左上角横排显示信号名（旋转的轴标题在矮行里会被截断，看不到） |
| **Y 轴** | 标题显示 DBC 信息：**有单位显示 `[rpm]`，没单位显示短信号名**（如 `E_IPUR_StMode`，过长截断）；**枚举信号的刻度直接用 DBC 的 `VAL_` 文本**（`Off`/`Ready`/`OFF`…），而不是 0/1/2 数字 |
| **鼠标读值** | 鼠标在图形区移动，每行**右上角**实时显示该时刻的值（V0.2dev/Thursday 新增）；表头显示 `鼠标 t = …`。**任意一行上都有效**，吸附基准是"鼠标所在的那一行" |
| **采样点** | 默认在真实采样点处画圆点；**每行可见点数超过 3000 时自动隐藏**（否则糊成色块），放大后自动出现。视图菜单/右键可整体关闭 |
| **极值标记** | 每行画 min/max 水平虚线（常量行不画）；**可全局关，也可单行关**：值表最后一列勾选框，或右键该行「本行显示极值标记 / 恢复跟随全局」。行级设置会存进布局 |
| 光标手柄条 | 图形区上方那条灰带：**整条都能点拖**；单光标一个绿色手柄，双光标时两光标之间显示 ΔT |
| 底部值表 | 每行的**行统计**（最小/最大/均值）；单光标显示“光标值”，双光标显示 T1/T2 与差值 |

> **吸附采样点**（默认开）：鼠标读值与双光标都吸附到**真实帧时刻**，
> 避免"保持前一值"语义下"看起来 40、其实 39"的读数错觉。工具栏「吸附采样点」/ 右键 / `Ctrl+Shift+L` 切换。

### 两种坐标系布局

| 布局 | 说明 |
|---|---|
| 多轴堆叠（默认） | 一行一个坐标系、**Y 轴各自独立**，适合看不同量纲（转速 / 温度 / 状态位） |
| 单坐标轴叠加 | 所有信号叠加进**同一个坐标系、共用一个 Y 轴**（左上角带图例），适合看相互比例与相位关系。工具栏/视图菜单 `Ctrl+G` 或图形区右键切换 |

### 快捷键

| 快捷键 | 功能 |
|---|---|
| `Ctrl+O` | 打开 ASC |
| `Ctrl+M` | 双光标测量开关 |
| `Ctrl+Shift+M` | 单光标测量开关（与双光标互斥） |
| `Ctrl+Shift+Y` | Y 轴跟随缩放开关（默认开启） |
| `Ctrl+G` | 单坐标轴叠加开关 |
| `Ctrl+Shift+L` | 吸附采样点开关（读值与双光标） |
| `Ctrl+Shift+C` | 导出 CSV（分号：双光标已定位时只导出光标区间） |
| `Ctrl+Shift+P` | 导出 PNG（含标题、手柄条、曲线） |

### 时间轴四种模式

| 模式 | 用途 |
|---|---|
| 原样时间 | 直接用 ASC 时间戳（相对文件起点，单位秒） |
| 空档压缩 | 把长空档/回退切成段拼接，长空档报文更紧凑 |
| 全局帧序号 | 用帧在文件中的顺序做 X 轴；**源文件时间戳乱序时最稳**（见下） |
| **GPS 时间** | 从 **0x3A5 RTC 帧**的日期/时间字段推出绝对时间；刻度显示 `HH:MM:SS`，鼠标读值/双光标/CSV 也显示绝对时间 |

### 光标与 Y 轴

- **单光标测量**（`Ctrl+Shift+M`）：一条绿色可拖动光标，值表只显示“光标值”和行统计；
  适合快速读某一时刻，不需要 T1/T2 差值。
- **双光标测量**（`Ctrl+M`）：T1/T2 + ΔT，和单光标互斥。
- **Y 轴跟随缩放**（`Ctrl+Shift+Y`，默认开启）：缩放/平移 X 轴时，按当前可见数据自动适配
  各行 Y 轴；关闭后 Y 轴保持手动缩放。单坐标轴叠加时按所有可见行的并集适配。

![单光标与 Y 轴自动适配](reports/单光标与Y轴自动适配.png)

> 关于"日志形态"：`logCAN572/573/574` 这类样本时间戳单调；`logCAN8` 这类样本
> 内部存在多段时间基准（同通道回退 9798 次、跨度最高 117 小时），此时建议用
> "全局帧序号"。工具在 M0 阶段已对样本做过体检，结论见 `开发计划.md` §二。

## 三、DBC 接入（可选）

### 1. 为什么需要"通道映射"

一个 DBC 通常只描述**某一条总线**，而一份 ASC 里有多个通道
（CANFD ch1/4/5/9/17/18/19/20 + 经典 ch3），所以必须指明「哪个 DBC 作用于哪个通道」。
支持**多个 DBC 同时生效**，分别映射到不同通道。

### 2. 怎么用（V0.3 拖拽工作台）

1. 把 DBC 拷进 exe（或项目）同级的 `dbc\` 目录，例如 `dbc\E CAN.dbc`；
   也可以直接把 `.dbc` 从资源管理器拖进工作台，程序会**自动复制到 `dbc\`**。
2. 菜单 **DBC → DBC 映射设置…** 打开工作台。**不打开 ASC 也能先配置**，
   左侧是 `dbc\` 目录，右侧是 21 条默认通道模板（1~21，含通道名称与备注）。
3. 把左侧 DBC **拖到右侧通道行**即完成映射；同一通道可以放多个 DBC，
   同一 DBC 也可以拖到多条通道。按住 `Ctrl` 点选多条通道行，可一次批量映射。
4. 通道名称、备注都可以**行内直接编辑**；备注会显示在左侧报文树的通道节点 tooltip 里。
5. 点 **应用** 才写入 `dbc\channel_map.json`（v2）；点“取消”不会落盘。
6. 左侧树里对应报文会显示 DBC 报文名与信号（名称/单位/取值域），双击信号即可成行。

> **帧类型不需要你选**：DBC 自己带着（Vector `VFrameFormat` 属性，如 `CANFDStandard`），
> 程序加载时自动识别，并把结果显示在工作台里（含报文数/信号数/帧格式/编码）。
> 若 DBC 用 CANFD 却拖到经典 CAN 通道，行内会给出橙色 `⚠` 提醒，但仍允许保存。

也支持命令行（便于与上游工具联动）：

```bash
BeneCAN.exe "D:\日志解压目录" --dbc dbc\CH5.dbc --channels 5,9
```

`--channels` 只写通道号即可（帧类型自动识别）；确需强制指定时用 `canfd:5,classic:3`。

`channel_map.json` 结构（v2，可手改）：

```json
{
  "version": 2,
  "channels": {
    "5":  { "name": "E CAN", "remark": "整车网络" },
    "18": { "name": "LDCU LIN", "remark": "LIN to CAN" }
  },
  "mappings": [
    { "dbc": "E CAN.dbc", "kind": "canfd", "channels": [5] },
    { "dbc": "CH5.dbc", "channels": [5], "comment": "历史字段，可保留" },
    { "dbc": "LDCU LIN.dbc", "kind": "canfd", "channels": [17, 18] }
  ]
}
```

- `channels` 只写**相对默认模板发生变化**的通道；没写的通道自动使用内置 21 条模板；
- `kind` 留空/不写 = 帧类型自动（由 DBC 判定）；程序写入时会把自动识别的结果记下来；
- v1 旧配置可直接读取（没有 `channels` 段时使用默认模板），无需手工迁移；
- 写入采用临时文件 + `os.replace`，并在覆盖前留一份 `channel_map.json.bak`。

### 3. 已验证的能力与注意事项

- **位序**：Intel（小端）与 Motorola（大端）都支持，含跨字节与位域；
  映射规则已用 cantools 自身编码做端到端对照（15 个信号 100% 一致）
- **编码**：自动识别 UTF-8 / GBK / latin-1。中文 DBC 常见 GBK，
  且 cantools 默认按 latin-1 读会乱码，工具已内置探测
- **帧类型**：读 DBC 的 `VFrameFormat`（数字 14/15 或文本 `CANFDStandard` 都认）；
  全部报文同一种就据此限定映射，混用或没写则不限制（按任意帧类型匹配，避免 DBC 不生效）
- **DBC 语法限制**：报文/信号**名字**必须是 ASCII（中文只能出现在单位、`VAL_` 枚举文本、`CM_` 注释里）
- 若 DBC 报文长度与日志长度不一致，树里会给出提示行，提醒确认映射
- 同一报文被多个 DBC 命中时以第一个为准（同通道内按拖入顺序，状态栏会提示）
- 未加载 DBC 时全部功能照常可用（走逐字节自动识别）
- DBC 解析失败的文件在工作台里标红、禁止拖拽；不会影响其他 DBC 与已有映射

### 4. GPS 时间轴（0x3A5 RTC）

时间轴下拉选择 **GPS 时间** 即可。程序扫描日志里的 `0x3A5`，从 RTC 字节直接还原
日期/时间（不要求 DBC 里有这个报文），默认字段布局：

| 字节 | 字段 | 说明 |
|---|---|---|
| byte0 | year | `2015 + byte0`（当前样本：0x0B → 2026） |
| byte1 | month | 低 4 位 |
| byte2 | day | 低 5 位 |
| byte3 | hour | 低 5 位 |
| byte4 | minute | 低 6 位 |
| byte5 | second | 低 6 位 |
| byte6 | timezone/status | 本版不参与换算 |

行为：

- 自动在主通道（ch1 → ch4/5/9/17/3…）中找有有效 RTC 的 `0x3A5`；
- 用连续一致的样本拟合时间段，**交织的另一套时间源/末尾时间回退**会被切成独立段；
- 时间轴按段连续拼接，刻度显示 `HH:MM:SS`；跨段处画橙色虚线并标注新的绝对时间；
- 鼠标读值、T1/T2、CSV 时间列都输出 `YYYY-MM-DD HH:MM:SS`；
- 日志里没有有效 `0x3A5` 时，切 GPS 会明确提示并保持原模式，不影响其他功能。

验证截图：[logCAN572（干净 RTC）](reports/GPS时间轴-logCAN572.png)、
[logCAN8（含 RTC 回退）](reports/GPS时间轴-logCAN8.png)。

> 限制：RTC 按现场日志的字段布局解码，时区字节暂未参与换算（显示的是 TBOX 给的本地时间）；
> 如果后续 DBC 的 `0x3A5` 定义不同，需要调整 `signals/gps_time.py` 的 `RtcLayout`。

## 五、数据与性能（实测）

| 项 | 数值 |
|---|---|
| 首次建索引（566 MB / 334 万帧） | 27~32 s（后台线程 + 进度条，不卡界面） |
| 索引体积 | 约 30 MB（压缩 16~19 倍），二次打开命中缓存 |
| 打开（索引已存在） | 0.9 s |
| 单报文取数（16.5 万帧） | 13~26 ms |
| 图形渲染（12 行 / 114 万点） | 0.16 s |
| 峰值内存（建索引） | 约 700 MB |

索引缓存位置：`%TEMP%\BeneCAN\index\`（可用环境变量 `BENECAN_INDEX_DIR` 改到别处）。
> V0.1 更名为 BeneCAN 后缓存目录随之改变，旧索引不会命中（首次打开会重建一次，属正常）。

## 六、日志（排查问题先看这里）

| 项 | 说明 |
|---|---|
| 位置 | `logs\BeneCAN_<日期>_<时间>.log`（源码运行 = 项目根；exe = **exe 同级**） |
| 级别 | 测试调试阶段**默认 DEBUG（全量）** |
| 临时改级别 | 启动前设置环境变量，如 `set BENECAN_LOG_LEVEL=INFO`（或 `WARNING`） |
| 滚动 | 单文件 5 MB，保留 5 份 |
| 内容 | 启动环境与版本、打开 ASC/索引命中与建索引用时、DBC 解析与映射、树填充、
行增删与**图形重建耗时**、光标/布局切换、导出、**未捕获异常**、Qt 自身的告警 |
| 兜底 | 未捕获异常、Qt 的 qWarning/qFatal 都写进同一份日志。
**Qt 槽里的异常也走这里**（PySide6 6.x 把 Python 回调抛出的异常交给 `sys.excepthook`，
不会像旧版那样只往 stderr 打一份），所以"点了没反应"在日志里查得到；
日志目录不可写时自动退到临时目录 |

日志示例：

```
2026-09-23 18:16:39.686 | DEBUG | ui.msg_tree      | 报文树填充完成：1 通道 / 63 报文 / 53 个 DBC 命中 | 耗时 26 ms
2026-09-23 18:16:39.753 | DEBUG | ui.graphic_window| 重建图形：3 行 / 3213 点 | 多轴堆叠 | 时间轴 time | 双光标 False | 耗时 34 ms
2026-09-23 18:16:39.907 | INFO  | ui.graphic_window| 图形区渲染 PNG：...\g.png（55.0 KB，耗时 56 ms）
2026-09-24 08:35:19.900 | CRITICAL | benecan.unhandled | 未捕获异常     ← "点了没反应"的元凶，回溯紧随其后
```

> 排查"界面点了没反应"：搜 `未捕获异常` 或 `benecan.unhandled`，回溯就在这一行下方。
> 若确认整份日志里都没有，说明不是异常被吞，而是逻辑/信号未连接。
